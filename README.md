# GaragePro — ระบบจัดการอู่ซ่อมรถยนต์

เว็บแอปภาษาไทย รองรับมือถือ โครงสร้างสำหรับ GitHub + Netlify + Supabase

## ฟังก์ชันในชุดเริ่มต้น
- เข้าสู่ระบบ / สมัครบัญชีผ่าน Supabase Auth
- ภาพรวมจำนวนลูกค้า รถ งานซ่อม และอะไหล่ใกล้หมด
- CRUD ลูกค้า รถยนต์ ใบรับซ่อม และคลังอะไหล่
- สถานะงานซ่อม, ช่างผู้รับผิดชอบ, ราคาประเมิน/ยอดซ่อมจริง
- รายชื่อทีมงานสำหรับผู้ดูแล (สร้างบัญชีพนักงานต้องเพิ่มผู้ใช้ใน Supabase Auth ก่อน)
- SQL schema มีตารางสำหรับรายการอะไหล่ต่อใบซ่อม, ใบเสนอราคา และชำระเงิน พร้อม RLS policies

> หมายเหตุสำคัญ: หน้าจอ CRUD ที่ทำงานในเวอร์ชันนี้ครอบคลุมลูกค้า รถ ใบรับซ่อม และอะไหล่ ส่วนการจัดการใบเสนอราคา/รับชำระเงิน/เบิกอะไหล่รายใบซ่อมมีตารางฐานข้อมูลเตรียมไว้ แต่ยังไม่มีหน้าจอ workflow แยกในรุ่นนี้ จึงไม่ควรถือว่าเป็นระบบบัญชี/การเงินเต็มรูปแบบจนกว่าจะเพิ่มและทดสอบส่วนนั้น

## 1. ฐานข้อมูล Supabase
โปรเจกต์ `GaragePro` ถูกสร้างแยกจาก `MDBadmintonLive` แล้ว และติดตั้งตารางหลักพร้อม RLS บนโปรเจกต์ใหม่นี้เรียบร้อยแล้ว URL และ publishable key ถูกตั้งค่าไว้ใน `app.js` แล้ว ไม่ต้องรัน SQL ซ้ำในโปรเจกต์นี้

> `supabase/schema.sql` เป็นเอกสารสคีมาสำหรับการตรวจสอบ/ติดตั้งใหม่เท่านั้น ห้ามรันสคริปต์เก่าที่มีชื่อ `work_orders` ในโปรเจกต์ GaragePro ปัจจุบัน เพราะสคีมาที่ติดตั้งจริงใช้ `repair_orders`

ใช้เฉพาะ Project URL และ publishable key (หรือ legacy anon key) ในเว็บเท่านั้น **ห้ามใส่ service_role/secret key ในเว็บ**

## 2. ตั้งบัญชีผู้ดูแลคนแรก
1. สมัครบัญชีจากหน้าเว็บ
2. ใน Supabase Dashboard → Authentication → Users คัดลอก User UID
3. ใน SQL Editor รันคำสั่งโดยแทน UUID ให้ตรงกับ UID ของคุณ:

```sql
update public.profiles set role = 'admin' where id = 'ใส่-USER-UUID-ตรงนี้';
```

การเลื่อนสิทธิ์ครั้งแรกทำใน Dashboard เท่านั้น; อย่าเปิดให้ผู้ใช้สมัครแล้วเลือก role เอง

## 3. ทดสอบในเครื่อง
เปิด `index.html` ผ่าน local web server (เช่น VS Code Live Server) ไม่แนะนำเปิด `file://` โดยตรง เพราะบาง browser จำกัดการโหลดสคริปต์

## 4. Deploy Netlify
- สร้าง repository ใหม่ใน GitHub เช่น `garagepro` แล้วอัปโหลดไฟล์ทั้งหมดนี้
- Netlify → Add new site → Import an existing project → เลือก repository
- Publish directory: `.` (ไม่มี build command สำหรับรุ่น static นี้)
- Deploy site แล้วลอง login และบันทึกข้อมูลจริง

## ข้อจำกัด/สิ่งที่ต้องทดสอบก่อนใช้งานจริง
- ต้องตั้งค่า Supabase URL/key และรัน SQL ก่อน เว็บจะยังไม่เชื่อมฐานข้อมูลจนกว่าจะทำสองอย่างนี้
- ต้องกำหนดสิทธิ์ admin ให้ผู้ดูแลคนแรกตามขั้นตอนด้านบน
- ลูกค้าจะเห็นข้อมูลตัวเองเมื่อผูก `customers.user_id` กับ UID ของบัญชี Auth ใน Supabase
- หน้าทีมงานแสดงรายชื่อโปรไฟล์; การเชิญ/สร้างบัญชีพนักงานยังต้องทำใน Supabase Auth Dashboard
- ควรทดสอบ RLS ด้วยบัญชี admin, mechanic, staff และ customer แยกกันก่อนนำข้อมูลจริงเข้าระบบ
- ตารางฐานข้อมูลรองรับใบเสนอราคา รายการซ่อม การชำระเงิน และประวัติสถานะ แต่หน้า workflow แยกสำหรับรายการซ่อม/ใบเสนอราคา/ชำระเงิน/แนบรูปยังต้องพัฒนาต่อก่อนถือเป็นระบบเต็มรูปแบบ
